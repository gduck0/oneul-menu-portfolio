# 하루 식단 추천과 변경

공식 음식 자료에 연결한 메뉴 후보에서 하루 식단을 구성한다. 끼니 적합성·준비 조건·선호/제외·분량 범위·목표와의 차이·하루 다양성을 규칙으로 평가한다. 모델이 음식이나 영양값을 생성하는 방식은 아니다. 후보 수와 조건 때문에 모든 목표를 동시에 만족한다고 보장하지 않는다.

## API

| 요청 | 동작 |
| --- | --- |
| `GET /api/planner/menus` | 메뉴 후보·출처·참고 영양·준비 정보 조회 |
| `GET /api/planner/menu-exclusion-check` | 등록 메뉴 또는 직접 입력 이름과 요청한 제외 조건의 충돌 확인 |
| `GET /api/food-groups` | 음식 이름을 묶어 표시하되 업체·단위·원본 variant는 보존 |
| `POST /api/plans` | 하루 계획 생성 |
| `GET /api/plans` | 본인 계획 목록 |
| `GET /api/plan-history` | 본인 계획 목록과 전체 개수 |
| `GET /api/plans/{plan_id}` | 계획 조회 |
| `PATCH /api/plans/{plan_id}` | 끼니/구성 음식·분량·고정·추천 변경 되돌리기 |

메뉴를 직접 정하거나 양을 바꾸는 것은 계획 수정이다. 실제 섭취량은 별도 기록으로 저장한다. `POST /api/plans/{plan_id}/meals/{meal_key}/record`와 `GET /api/plans/{plan_id}/actual-meals`의 계약은 [기록 안내](records.md)를 참고한다.

## 요청과 설정

생성에는 `client_request_id`, `plan_date`, `energy_target`, `meal_count`, `constraints`, `fixed_meals` 등을 보낸다. 열량은 기본 1800, 허용 600~5000이며 끼니 수는 2·3·4 중 하나다. 2끼는 점심·저녁, 3끼는 아침·점심·저녁, 4끼에는 간식이 추가된다. 이 입력 범위는 개인에게 적합한 열량을 진단하는 기준이 아니다.

로그인 계정 또는 체험 브라우저의 저장된 목적·선호/제외/평소 음식을 읽는다. `preference`를 지정하면 해당 요청의 목적을 우선하고 `personalize=false`면 저장 취향과 평가 순위 반영을 끈다. 목표 열량·끼니 수·조리 조건은 생성 요청의 값이다. 저장한 기본값을 사용하려면 호출자가 `/api/preferences`를 조회해 이번 요청에 합쳐 보내야 하며, 서버가 모든 기본 설정을 자동 병합한다고 가정하면 안 된다.

후보 조회·충돌 확인의 `avoided_foods`도 호출자가 전달한다. 자동 추천은 저장 취향과 요청 끼니 조건을 적용한다. 수동 선택은 제외 충돌을 알리는 조회를 제공하되 직접 선택 자체를 금지하지 않는다. 이 확인은 메뉴명·참고 재료 기반이며 전체 성분·알레르기 안전 판정이 아니다.

## 고정·부분 변경·되돌리기

변경 요청에는 새 `client_request_id`, 현재 `expected_version`, `meal_key`, `action`을 보낸다.

- `lock`: 끼니 고정/해제. 고정한 끼니의 자동 `replace`는 거절한다.
- `replace`: 선택한 끼니만 재추천한다. 다른 끼니의 음식·양·고정 상태는 유지한다.
- `set`: 끼니 전체를 등록 메뉴 또는 직접 입력 음식으로 정한다.
- `add`, `remove`, `update_item`: 고유 `item_id`로 구성 음식 하나를 추가·삭제·변경한다. 밥·국·반찬 세트도 각각 수정할 수 있다.
- `portion`: 구성 음식 하나의 분량을 바꾼다. 등록 메뉴는 실제 양이 필요하고 직접 입력은 분량 모름을 허용한다.
- `undo_replace`: `replacement_request_id`로 해당 추천 변경 직전의 끼니 스냅샷을 복원한다. 중간에 직접 변경했다면 오래된 되돌리기는 거절한다.

직접 수정은 끼니 전체 고정과 별개다. 고정된 끼니도 사용자가 구성 음식을 직접 수정할 수 있으며 고정 상태와 다른 음식은 보존한다. 직접 입력만으로 끼니 전체를 자동 고정하지 않는다.

## 수치·결측·실패

등록 메뉴의 저장된 100g 기준 영양을 분량에 비례해 Decimal로 계산하고 둘째 자리로 반올림한다. 당시 참고값·공식 음식 출처를 보존해 분량을 다시 계산한다. 직접 입력 음식의 영양은 추정하지 않고 null로 남긴다. 확인된 영양 합계와 결측 항목을 나누고, 알 수 없는 항목이 있으면 하루 목표 달성 여부를 확정하지 않는다.

적합한 후보가 없으면 빈 끼니와 이유를 반환하며 제외·준비 조건을 임의로 완화하지 않는다. 선택지가 제한적이면 같은 메뉴가 반복될 수 있음을 설명한다. 사용자가 직접 고정한 중복 음식은 자동 다양성 조건으로 삭제하지 않는다. 메뉴 자료 전체가 준비되지 않았으면 새 가짜 계획을 만들지 않고 503을 반환한다.

같은 요청 ID·같은 본문의 재시도는 이전 결과를 반환하고 중복 생성/변경하지 않는다. 같은 ID의 다른 본문이나 오래된 버전은 409다. 다른 소유자의 계획은 목록에 보이지 않으며 조회·수정은 404로 처리한다. 입력이 거절되면 기존 계획과 설정은 유지한다.
