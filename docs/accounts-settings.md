# 계정과 개인 설정

현재 단계에서는 계정·세션과 개인 설정 API를 제공한다. 기존 음식 검색·상세 조회·분량별 영양 계산은 그대로 사용할 수 있다. 로그인·설정 화면은 후속 화면 반영 단계에서 연결한다.

## API

| 요청 | 동작 |
| --- | --- |
| `GET /api/auth/me` | 현재 계정 확인, 체험 브라우저 쿠키 준비 |
| `POST /api/auth/register` | 계정 생성 후 로그인 |
| `POST /api/auth/login` | 로그인, 이전 세션 교체 |
| `POST /api/auth/logout` | 현재 세션 삭제 및 로그아웃 |
| `GET /api/preferences` | 현재 계정 또는 체험 브라우저의 설정 조회 |
| `PUT /api/preferences` | 설정 전체 저장 |

가입·로그인은 `username`, `password`를 받는다. 아이디는 영문·숫자·한글·밑줄 3~30자이며 대소문자를 구분하지 않는다. 비밀번호는 10~128자다. 응답에는 계정 ID와 아이디만 포함한다.

## 설정 범위

- `goal`: 균형·열량·단백질·유사성 (`balanced`, `energy`, `protein`, `similarity`)
- `favorite_foods`, `avoided_foods`, `frequent_foods`: 각 10개, 이름당 40자 이하
- `energy_target`: 선택 입력, 하루 600~5,000 kcal
- `meal_count`: 2·3·4끼
- `default_constraints`: 끼니별 조리 여부, 준비된 반찬, 조리 도구, 소요 시간, 제외 음식

목표 열량의 입력 범위는 저장 검증 범위이며 개인에게 적합한 섭취량을 판정하는 기준이 아니다. 이름의 앞뒤 공백·중복은 정리하고, 같은 음식을 선호와 제외에 함께 저장하면 거절한다. 잘못된 입력은 기존 설정을 변경하지 않는다. `PUT`은 전체 교체이므로 부분 수정 시에는 먼저 조회한 설정에 변경값을 합쳐 보낸다.

계정 설정은 로그인한 계정에, 체험 설정은 해당 브라우저 쿠키에 연결된다. 가입·로그인만으로 체험 설정을 계정에 합치지 않는다. 쿠키가 없는 별도 브라우저의 체험 자료는 연결되지 않는다. 제외 음식은 취향·추천 조건이며 알레르기 안전 판정 기능이 아니다.

## 저장 구조와 실행

기존 `0002_food_catalog`에 `0003`~`0006` 마이그레이션을 순서대로 추가한다. 계정·설정뿐 아니라 다음 단계가 공유하는 추천·식단·기록·평가·이관 테이블도 준비한다. 이 단계에서는 계정과 설정 API만 연결하며, 공용 테이블이 존재한다는 이유로 추천·기록 기능이 완료된 것은 아니다.

기존 DB를 초기화하지 않고 아래 명령으로 업그레이드한다. 개발·테스트 대상과 로컬 비밀 설정은 유지한다.

```powershell
.\scripts\Migrate-Database.ps1 -Target dev
.\scripts\Migrate-Database.ps1 -Target test
.\scripts\Test-Backend.ps1
```

사용 중인 DB에 `downgrade`를 실행하면 해당 단계의 테이블·열이 삭제될 수 있으므로 데이터 초기화 용도로 사용하지 않는다.

## 세션과 요청 처리

비밀번호는 scrypt로, 세션 토큰은 SHA-256 해시로 저장한다. 세션은 7일, 체험 쿠키는 30일이며 `HttpOnly`, `SameSite=Lax`를 사용한다. 로컬 검토 앱과 구분하려고 쿠키 이름은 `oneul_portfolio_session`, `oneul_portfolio_guest`로 둔다. 쿠키는 포트별로 격리되지 않는다.

쓰기 요청은 JSON으로 받고, `.runtime.local.json`의 화면·API 포트에 해당하는 `127.0.0.1`·`localhost` 출처만 허용한다. 출처 헤더가 없는 직접 API 호출은 가능하며 브라우저의 교차 사이트 요청은 거절한다. API 응답에는 저장 방지 헤더를 붙이고, 입력 오류·DB 장애 응답에는 비밀번호 원문과 연결 정보를 싣지 않는다.

현재 로컬 HTTP에서는 `COOKIE_SECURE=false`가 기본값이다. HTTPS 운영 환경에서는 `COOKIE_SECURE=true`와 실제 운영 출처 설정이 필요하다. 로그인 실패 제한은 계정·접속 주소별 1분간 5회이며 단일 프로세스 메모리에 저장한다. 다중 서버 운영과 비밀번호 재설정은 현재 범위에 포함하지 않는다.

자동 검증은 테스트 DB의 트랜잭션 안에서 수행하고 롤백한다. 계정 분리·재로그인·세션 교체/만료·체험 설정 분리·입력 오류 시 보존·출처 차단과 기존 음식 기능을 함께 확인한다.
