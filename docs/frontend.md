# 화면 사용 흐름

로그인 없이 체험하거나 가입 후 개인 설정을 저장한다. 오늘 식단·식사 기록·내 설정 화면을 제공한다.

저장한 설정으로 하루 식단을 만들고, 끼니·구성 음식·분량을 바꿀 수 있다. 고정·직접 선택·제외 충돌 안내·직전 추천 변경 되돌리기를 제공한다. 저장 전 설정과 이번 식단의 조건은 구분하며, 분량을 모르는 직접 입력 음식은 영양을 임의로 추정하지 않는다.

화면은 [계정·설정](accounts-settings.md), [식단](planner.md), [기록·평가·이관](records.md) API를 사용한다. 과거 음식 대안 비교용 `/api/recommendations` 발급과 `/api/history`에는 의존하지 않는다.

실제로 먹은 뒤 계획한 양을 기준으로 절반·그대로를 고르거나 실제 양을 입력해 기록한다. 계획은 보존하고 기록한 양·시각을 별도로 수정·취소·복원한다. 완료한 끼니에서는 계획과 최신 실제 섭취 요약을 구분해 보여준다.

식사 평가는 만족도와 이유를 함께 남긴다. 등록 음식의 명시적인 맛·메뉴 취향 평가만 다음 추천의 취향 점수에 참고하고, 양이나 오늘 먹기 어려웠다는 의견은 해당 사유로 남긴다.

체험 자료는 로그인만으로 합치지 않는다. 가져오기를 선택해야 계정에 연결하며, 기존 계정 설정과 기록은 보존한다. ‘나중에’를 누르면 같은 브라우저·주소의 해당 계정에서 안내를 접어 두고 내 설정에서 다시 열 수 있다.

실행은 [로컬 안내](run.md)를 따른다. 폰트·그림과 라이선스를 보존하며 그림은 음식 종류의 예시다. 화면 표시 열량은 개인 권장량 진단이 아니다.

## 회귀 검사

frontend 폴더에서 `pnpm test`로 자동 회귀 검사를 실행하고 `pnpm build`로 테스트 파일을 포함한 타입 검사와 배포 빌드를 확인한다. Node.js는 설치 안내의 검증 버전을 사용한다. 테스트 실행은 브라우저·API·DB를 시작하거나 기존 저장 자료를 수정하지 않는다.

음식 그림 연결, 목표 열량 차이·분량 미리보기, 준비 조건과 체험 이관 보류 상태의 보존을 검사한다.

이 검사는 전체 브라우저 사용성 검사와 구분한다. 사용자 흐름은 해당 버전의 화면·API를 연결해 별도로 확인한다. 현재 주소와 화면에 맞지 않는 과거 대안 비교용 브라우저 검사는 현재 실행 검사 목록에 포함하지 않는다.
